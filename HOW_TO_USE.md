# 📘 How, Where & Why to Use This Project

## Project
**eStartup — Responsive Startup & App Landing Page**

## Why Use It

This repository demonstrates a feature-rich startup website with app promotion, feature blocks, screenshots, course content, team profiles, pricing, AOS animations, Swiper sliders, GLightbox media, and responsive Bootstrap components.

Use it to:

- Study a complete startup landing-page structure
- Practise Bootstrap, JavaScript, AOS, Swiper, and GLightbox
- Learn app-promotion and pricing interfaces
- Build portfolio evidence for interactive front-end development
- Review vendor asset and plugin organisation

## Where It Can Be Used

- Startup and app prototypes
- Front-end portfolios
- Training and coursework
- SaaS marketing-page practice
- Plugin integration demonstrations

> Replace all template content, product claims, store links, pricing, team data, and contact details before publishing.

## How to Use It

```bash
git clone https://github.com/samusa099/Project_01.git
cd Project_01
```

Open `index.html` or use **VS Code Live Server**.

### Customisation Steps

1. Update hero, features, app links, course, team, pricing, and contact content in `index.html`.
2. Replace screenshots and brand imagery inside `img/`.
3. Edit project styles inside `css/`.
4. Review plugin configuration inside `js/`.
5. Keep required libraries inside `vendor/` unless replacing them with maintained versions.
6. Test animations, sliders, lightbox, and mobile navigation.

## File Guide

| File or Folder | Purpose |
|---|---|
| `index.html` | Main startup landing page |
| `css/` | Project and supporting styles |
| `js/` | Main interactions and plugin initialisation |
| `img/` | Brand, hero, screenshots, team, and interface assets |
| `vendor/` | Bootstrap, AOS, Swiper, GLightbox, icons, and libraries |
| `README.md` | Project overview |
| `HOW_TO_USE.md` | Detailed usage, customisation, and deployment guide |

## Recommended Workflow

1. Audit and replace template content.
2. Prepare consistent product screenshots.
3. Update navigation and section order.
4. Test each plugin after changes.
5. Verify pricing, calls to action, and links.
6. Review accessibility, performance, and SEO before deployment.

## Suitable Practice Tasks

- Connect app-store links
- Build dynamic pricing cards
- Replace static screenshots with product media
- Add a working contact form
- Improve animation performance
- Deploy with GitHub Pages

## Limitations

- Static front-end project
- No authentication, payment, or product backend
- Store, pricing, and contact actions are placeholders
- Third-party libraries and assets require licence review
